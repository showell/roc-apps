A report for the Roc team on 0.1.0_RC1. Claude, an AI coding agent, made the moves, ran the measurements and wrote this page under Steve's supervision.

Summary

Possible issues for the Roc team

  • Dev builds default to boxy lowering (every roc build but --opt=speed). KnightProof ran 22 times slower built with --opt=dev: 344.7 s of CPU, against 15.6 s on the old nightly; 15.8 s with --specialize=yes, which our chess gate now passes. Read more below.
  • A "duplicate definition" warning we're unsure is intended, for a nested type's member named like the outer type's (Crate.width, Crate.Lid.width). The program runs correctly. roc-chat's five such renames: e8e8a84. Read more below.
  • Cold checks took about 2.4 times the CPU in roc-syntax-color and roc-markdown (under 1.5 s each); the same in roc-screensaver and roc-chat, less in roc-apps. Read more below.
  • Release outputs are 8 to 13% bigger. Read more below.

"Green" in roc-apps: roc check of 51 apps, Safari's gate (974 expects, 20 widgets and 1089 of their tests, the page's drawing at its frozen checksum), the chess, Dog Park, Seattle Delivery and book_builder gates; in roc-screensaver, its 34 checks, Windows cross-builds included.

Things we simply had to fix in our own code

  • The shadowing warning, now reaching a type's own members: 83 renames. Read more below.
  • Unsuffixed literals whose only constraints are method calls ((0.0).to_bits()): 14 given a type. Read more below.
  • The nominal check caught Safari passing a plain record where Cat and Bird were wanted. Read more below.
  • Glue: on_copy and capture_size in the erased callable's payload, new RocOpaqueList and RocHeldList; regenerated, seam checks green. Read more below.
  • Native roc-ray builds retired: roc-ray hasn't moved to RC1 yet (15 nominal errors in our checkout). Read more below.

What moving cost us

  • 83 renames (31 roc-apps, 48 roc-chat, 4 roc-screensaver): shadowing. Our gates fail on any warning.
  • 5 nested-member renames in roc-chat, 51 call sites: duplicate definition.
  • 14 typed literals (5 roc-apps, 9 roc-screensaver): literals.
  • Safari's Cat and Bird built as nominal values: nominal check.
  • Glue regenerated in book_builder, roc-chat and roc-screensaver; roc-types passes BuildEnv.init's new specialization-strategy argument: glue.
  • --specialize=yes in the chess gate: boxy default.
  • Native roc-ray builds retired. Steve: "we have had successful roc-ray builds in the past but stopped verifying native builds after some compiler churn". roc-ray isn't ours to move.
  • roc-types' release build stripped, past an LLVM assertion in our patched Zig 0.17.1. Not Roc's.

Much of this was our own code being wrong: parameters hiding their function (our Safari book taught metres = |metres|) and a plain record standing in for a nominal type.

Dev builds default to boxy lowering

roc build --help: "Use lambda-set specialization (yes, the --opt=speed default) or boxy lowering (no, the default otherwise)". Safari's dev-built proof tools took 56 s either way; KnightProof's search (CPU s, one run):

With the flag the chess gate went from 593 s to 24.7 s. Our workaround:

roc-apps canvas_apps/chess_kit/gates/run.shale, lines 44-49, at a44c405

-- `--specialize=yes` because Roc 0.1.0_RC1 lowers a dev build the boxy way
-- unless told otherwise, and KnightProof's search ran 22 times slower so: 344.7 s
-- of CPU, against 15.8 s specialized (15.6 s at nightly-2026-11-03-34bd006).
function hold_proof(roc, toy, work)
  local bin = real(work) .. "/" .. toy.proof
  local b = run({roc, "build", "--opt=dev", "--specialize=yes", toy.proof .. ".roc", "--output=" .. bin}, {cwd = toy.folder, timeout_ms = 600000, tail = 40, nice = 19, want = WANT})

"Duplicate definition" for a nested type's member

A bare width inside Lid would mean the inner one, so this may be intended. But the two are only reached qualified, and if it is intended, a message other than "duplicate definition" would help.

Crate.roc

Crate := { width : U64 }.{
	width : Crate -> U64
	width = |Crate.(crate)| crate.width

	Lid := { width : U64 }.{
		width : Crate.Lid -> U64
		width = |Crate.Lid.(lid)| lid.width
	}
}

main.roc

app [main!] {}

import Crate

main! = |_args| {
	echo!("${Crate.width(Crate.({ width: 3 })).to_str()} ${Crate.Lid.width(Crate.Lid.({ width: 4 })).to_str()}")
	Ok({})
}

RC1 runs it correctly (3 4); the old nightly checks it clean. roc-chat's five sites (AgentKey.Admitted.scope; signed_bytes in GitHubSignUp.Claim, GitHubState.Claim and Session.Claim; Users.Human.user) became granted_scope, bytes_to_verify and as_user, 51 call sites in one commit, e8e8a84.

The stricter nominal-type check

The old nightly let a plain record unify with a nominal type through an alias's parameter, and printed Sit:

Cat.roc

Cat := { pose : [Sit, Run] }.{
	pose_of : Cat -> [Sit, Run]
	pose_of = |c| c.pose
}

main.roc

app [main!] {}

import Cat

Wrapped(kind) : { animal : kind }

wrap : pose -> Wrapped({ pose : pose })
wrap = |pose| { animal: { pose } }

cat : [Sit, Run] -> Wrapped(Cat)
cat = |pose| wrap(pose)

main! = |args| {
	pose = if (args.len() > 1) Run else Sit
	echo!(Str.inspect(cat(pose).animal.pose_of()))
	Ok({})
}

roc check main.roc, at 0.1.0_RC1

── ✗ type mismatch ────────────────────────────────────────────── main.roc:11:14

This expression is used in an unexpected way.

cat = |pose| wrap(pose)
             ^^^^^^^^^^

It has the type:

    Wrapped({ pose: [Run, Sit] })

But the annotation says it should be:

    Wrapped(Cat)

A plain record is never the same as a nominal type like Cat, even when it has
exactly its fields.

Hint: To use Cat here, write Cat instead of the record type in the type
annotation that says it's a plain record. You can also convert between Cat and
a plain record with Cat.{ ... }: build a value of type Cat from a record's
fields, or take one apart and build a record from its fields.

── 1 error and 0 warnings ───────────────────────────────────────────── main.roc

Safari did this with Cat and Bird (both :=). The fix passes in what the pose makes:

Unsuffixed literals and method calls

The old nightly checks this clean and prints 0:

main.roc

app [main!] {}

main! = |_args| {
	echo!((0.0).to_bits().to_str())
	Ok({})
}

roc check main.roc, at 0.1.0_RC1

── ✗ missing method ─────────────────────────────────────────────── main.roc:4:9

This number's type never resolved to a concrete type, so it has no to_bits
method.

echo!((0.0).to_bits().to_str())
       ^^^

Its type needs all of these:

    a where [a.to_bits : a -> b, b.to_str : b -> Str]

Giving the number a suffix, using it somewhere that requires a specific type,
or annotating it will give it one.

── 1 error and 0 warnings ───────────────────────────────────────────── main.roc

Build times

Five repositories, both compilers, under the announcement's four conditions: cold (cache emptied, then a hello-world built), warm (again at once), root changed and import changed (a comment appended to the root, or to the most-imported module). Median of three, seconds; the compilers alternated, each run niced with its own cache. The script; the TSV, with every run and the box's load.

Noisy (the box): roc-syntax-color's cold checks took 0.58, 7.44 and 9.47 s (old) and 10.64, 21.30 and 22.32 s (RC1) of wall time for about 0.5 and 1.3 s of CPU, and we don't know where the rest goes. roc-screensaver's release builds had outliers of 115.5 s (RC1) and 63 to 86 s (old). Trust a difference under 2 times only when the CPU agrees.

  • Cold checks: about 2.4 times the CPU in roc-syntax-color and roc-markdown, the same in roc-screensaver and roc-chat, less in roc-apps.
  • Warm: 10 to 64 times faster; roc-markdown's check 3 times (under 0.1 s), roc-chat's 1.8 and its dev build 6.2, roc-screensaver's test over 100.
  • Root changed: mostly 4 to 32 times faster (roc-screensaver's test 75, roc-chat's 107). roc-markdown's check 0.07 → 0.04 s; roc-syntax-color's 0.12 → 0.20 s wall but 0.05 → 0.02 s CPU; roc-chat's 0.38 → 0.69 s CPU, slower. Import changed: the same to 11 times faster.
  • Cold dev builds: the same, faster in roc-apps and roc-chat. Cold tests: mixed. Release builds: the same in roc-markdown, faster in roc-screensaver and roc-apps.
  • Release outputs 8 to 13% bigger. Dev outputs bigger in three (roc-syntax-color's 2.3 times, cause unknown), smaller in roc-chat (0.7 times) and roc-apps (half, the one wasm dev build).

The box

One shared DigitalOcean droplet: 2 CPUs (Intel, KVM), 7.8 GiB, no swap, Ubuntu 24.04, with other agent lanes running. We didn't wait for a clean box; each TSV row records the load average, and for roc-screensaver and roc-apps the count of other programs running.

What we found

  • The stricter checks caught real mistakes in our code: a plain record standing in for Cat and Bird, and 83 shadows, one in our book's teaching example.
  • Testing a release candidate turned up two things to report, the boxy default's cost to one program and the nested-member warning. That's what a release candidate is for.

Pinning note: the 0.1.0_RC1 tag is 15177e9, three commits before the announcement's 2eadd079; the binaries were built from 15177e9, and our pins name it.
