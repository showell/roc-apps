Safari Ride

A drive through the country, as a screensaver: hills, a winding road, herds, and a rider who leans into the turns. It began as a program in another language, Codex, translated to Roc by a tool; every one of its modules has since been rewritten. Space pauses, the arrows step through the ride, J jumps to the next intersection, R starts over.

Roc at workSafari Ride models a whole world with Roc's types. On each stretch of road a cat crosses, a bird flies over, or the road is quiet: three cases of one tag union, and the compiler checks that every match handles them all. A step of the ride answers [Continued(Tour), Restarted(Tour)], a union declared nowhere but in its function's signature. And every instant of the ride is a plain value, so stepping backward is just returning to an earlier one.

encounter_throttle : Encounter, Animation.Stage -> ThrottleLimit
encounter_throttle = |encounter, stage|
    match encounter {
        CatCrosses(_) =>
            match stage {
                Playing(_) => AtMost(Acceleration.steady)
                Waiting | Past(_) => NoLimit
            }
        BirdHere(_) | QuietRoad => NoLimit
    }

Safari Ride: a tour of a real Roc program

It teaches Roc through Safari Ride's real source: every code sample is quoted from the ride as the book is built, so the book and the code stay in step.

It starts from one page of the ride and works out to the whole program: types, tag unions, records, opaque types, pure functions and effects, each met where the ride needs it. Interactive widgets let you poke at the pieces. An early draft.

Roc at workThe book is built by a Roc program whose types keep its effects apart: one effectful main! prints the pages, and one pure -> function turns the chapters into every one of them, so its tests check whole pages as plain values.

roc-markdown

A finished, complete package, built to a professional standard and in production: a markdown renderer for chat, safe to show whatever a user typed. Each render carries a budget for its work, an ordinary value, so a message built to overload it is refused before it's shown. It renders Gopher Chat on lynrummy.com, and the playground runs it live.

Roc at workIn Roc only a platform can perform effects, and a package has none, so a renderer fed hostile input can't touch the disk or the network. The same pure functions render chat on a server and, compiled to WebAssembly, in your browser as you type.

BASIC

Written directly in Roc, not translated from another language, it runs two dialects, ECMA-55 Minimal BASIC and the BASIC of the 1978 Creative Computing games, and it's graded against the National Bureau of Standards' test programs and the classic games. The REPL runs here; the same interpreter runs as a command-line program.

Roc at workRoc's values never change, yet this BASIC interpreter updates its machine in place: Roc reuses a value's memory when nothing else refers to it, and the machine is shaped so nothing does. A check holds each of its small control programs to what one loop allocates, and most allocate nothing at all.

Fast Track

The marble race board game: you play red against them, and their marbles walk the board as they move. They never see a card they haven't drawn. The rules and the whole page are Roc, ported from Steve's Elm version; the computer players are new, written by Claude.

Roc at workThe game's rules are a pure Roc function, so the three computer players try every line of play through the rest of their turn with the real rules, and keep the one their strategy scores highest; no move ever has to be undone.

Luke's examples

roc-ray is Luke Boswell's Roc platform for 2D games, visual tools and interactive apps, powered by raylib, and it runs natively on macOS, Linux and Windows. These six toy retro games are roc-ray's own examples, all written by Luke, © 2024 Luke Boswell under the UPL. What this site adds is a proof of concept: Luke's apps also run as web pages, which is what you see here. They show the power of Roc in miniature.

Roc at workLuke's game rules are pure functions, a world in and the next world out: their signatures use ->, not =>, so the compiler guarantees they do no I/O. So the rules moved to the browser with their arithmetic untouched, changing only import lines and a file name or two. Claude adapted the rest for the browser, a light modification: the drawing was rewritten, from roc-ray's drawing calls to a frame described as a value, and each ported file says in its own comment what changed and why. The same files still type-check against roc-ray.
