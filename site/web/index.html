Safari Ride

Safari Ride models a whole world with Roc's types: on each stretch of road a cat crosses, a bird flies over, or the road is quiet, three cases of one tag union, and the compiler checks that every one is handled. And every instant of the ride is a plain value, so stepping backward is just returning to an earlier one.

A drive through the country, as a screensaver: hills, a winding road, herds, and a rider who leans into the turns. Space pauses, the arrows step through the ride, J jumps to the next intersection, R starts over.

Safari Ride: a tour of a real Roc program

A little book that teaches Roc through Safari Ride's real source, and is itself built by a Roc program: one pure function turns the chapters into every page, and every code sample is quoted from the ride's source as the book is built, so the book and the code stay in step.

It starts from one page of the ride and works out to the whole program: types, tag unions, records, opaque types, pure functions and effects, each met where the ride needs it. Interactive widgets let you poke at the pieces. An early draft.

roc-markdown

A Roc package with no platform runs anywhere Roc does: the same pure functions render chat on a server and, compiled to WebAssembly, in your browser as you type.

A markdown renderer for chat, safe to show whatever a user typed. Each render carries a budget for its work, an ordinary value, so a message built to overload it is refused before it's shown. It renders Gopher Chat on lynrummy.com, and the playground runs it live.

BASIC

Roc's values never change, yet this BASIC interpreter updates its machine in place: Roc reuses a value's memory when nothing else refers to it, and the machine is shaped so nothing does, so most of its small control programs loop without allocating at all.

Written by hand in Roc, it runs two dialects, ECMA-55 Minimal BASIC and the BASIC of the 1978 Creative Computing games, and it's graded against the National Bureau of Standards' test programs and the classic games. The REPL runs here; the same interpreter runs as a command-line program.

The game's rules are a pure Roc function, so the three computer players can try every line of play through the rest of their turn with the real rules, and keep the one their strategy scores highest; no move ever has to be undone. They never see a card they haven't drawn.

Luke's examples

roc-ray is Luke Boswell's Roc platform for 2D games, visual tools and interactive apps, powered by raylib, and it runs natively on macOS, Linux and Windows. These six toy retro games are roc-ray's own examples, all written by Luke. What this site adds is a proof of concept: the same Roc files also run as web pages, which is what you see here. They show the power of Roc in miniature. Luke's game rules are pure functions, a world in and the next world out, and Roc's types say so, so the rules moved to the browser with only their import lines changed. Only the drawing was rewritten, from roc-ray's drawing calls to a frame described as a value, and the same files still type-check against roc-ray.
