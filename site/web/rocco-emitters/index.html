A dust devil in Rocco: building with Emitters

Steve has used Claude to build a small app with Rocco, Braeden Foster's 3D engine for games written in Roc. The app is Safari Walk, a ride down a savanna road at sunset (its source). Steve is happy to report that the package provides lots of functionality with almost no pitfalls. He mostly directs Claude to build things out, and wears the "movie director" hat more than the "quality assurance" hat. The code on this page shows a typical module that exploits a key feature of Rocco, the Emitter paradigm.

The module is game/DustDevil.roc. As the ride goes on, a whirl of dust rises on the verge, wanders across the road in the low sun, flinging bits of grass round in it, and falls apart behind the jeep. Every snippet below is quoted from safari-walk at commit ba237da, or from Rocco at commit 565ec02, the engine that commit builds on, with a link to its lines.

The Emitter paradigm

A Rocco game is a Roc app: a model and a few pure functions. Each frame, its view returns a Scene, a plain value that lists the camera, the lights, the meshes and, in a field called emitters, the particle sources. The game never moves a particle. An Emitter is a record that describes a source as it is now: where it is, how many particles a second it emits, how long they live, how they grow, change colour, drift and spin. Rocco's host simulates every particle from that description.

Two consequences shape everything below. When a source's settings change from one frame to the next, the particles already in the air follow the new settings. When a source leaves the list, it stops emitting, and its particles drain away with their last settings. So a whole dust devil can be a pure function from how far the walk has come to a short list of records. The record's doc comment is the engine's whole contract for it:

## `id` identifies a source independently of Draw ids. The first duplicate wins.
## Removal stops emission; existing particles drain with the last settings.
...
## Size and colour interpolate across each particle's lifetime, in world units

## The outdoor fields, each 0 for none:
## - `acceleration` is added to every particle's velocity each second, before
##   drag: gravity for falling dust or spray, a lift for rising smoke.
## - `spawn_radius` starts each new particle at an even random place on a
##   level disc of that radius round `position`, not at `position` itself.
## - `swirl` turns every particle about the upright line through the
##   source's current `position`, in radians a second, counter-clockwise
##   seen from above: a dust devil, a whirlpool, leaves in an eddy.
## - `outward` moves every particle straight away from that line, in metres
##   a second (negative: in toward it), never past it.
## `time_scale` is the source's own clock against the host's step: 1 runs
## at the host's pace, 0 holds its particles still and emits none, so a game
## with its own pause or tempo keeps its particles on its clock.
## Acceleration and outward clamp to +/-1000000, spawn radius to
## 0..1000000, swirl to +/-1000 and time scale to 0..100.
Emitter : { id : U64, position : Vec3, rate : F32, lifetime : F32, start_size : F32, end_size : F32, start_colour : Rgba, end_colour : Rgba, velocity : Vec3, velocity_spread : Vec3, drag : F32, acceleration : Vec3, spawn_radius : F32, swirl : F32, outward : F32, time_scale : F32, seed : U64, image : U32, blend : [Alpha, Add] }

Rocco also gives Emitter.default, a stationary, soft, round source whose doc says to set an id and a rate before use. Every builder below starts from it.

Two halves: the game's state, then the Emitters

The module splits in two, and the seam between the game and Rocco runs between the halves. This drawing is the whole flow, from the walk to the host:

The game's half works out the devil from the walk. A Watcher is the walk as the devil is seen from it, and state turns it into a State: where the foot is, how fast it travels, how strong it is, the colour the sun and the haze give its dust, and the clock its particles run on. This is plain game code. Of Rocco it uses only the vector and colour types, and it knows nothing about particles:

game/DustDevil.roc, lines 36-60

## The walk as the devil is seen from it: `walked` metres down the road,
## `walking` or paused, the walker's `eye`, and the light of `moment`.
Watcher : {
	walked : F32,
	walking : Bool,
	eye : Vocabulary.Vec3,
	moment : Daylight.Moment,
}

## The devil at one moment, all of it ours: its `foot` on the ground and
## its `travel` across the road (in metres a walk second), its `strength`
## from 0 as it rises to 1 and back to 0 as it falls apart, the colour
## `lit` its dust takes from the sun and the haze, and the `clock` its
## particles run on (the walk's tempo, or 0 while paused).
State : {
	foot : Vocabulary.Vec3,
	travel : Vocabulary.Vec3,
	strength : F32,
	lit : Vocabulary.Rgb,
	clock : F32,
}

## The devil as `watcher` sees it: `Up` while it whirls, `Down` before
## it rises and after it falls apart.
state : Watcher -> [Up(State), Down]

Down covers the time before the devil rises and after it falls apart. Everything about the devil's path, its rise and fall, and its light lives in small functions below state, and none of them builds an Emitter.

The half that crosses to Rocco is three builders, column, skirt and flecks. Each takes the State and returns one Emitter. They are the only code in the module that builds Emitters, and the module's whole output is a match on the state:

game/DustDevil.roc, lines 82-92

## The particle sources while the devil is up: its state, handed to
## Rocco as three Emitters.
emitters : Watcher -> List(Vocabulary.Emitter)
emitters = |watcher| match state(watcher) {
	Up(devil) => [
		column(devil),
		skirt(devil),
		flecks(devil),
	]
	Down => []
}

One builder, whole

The column is the main body of the devil: dust rising from a disc round the foot, spinning, lifting and flaring into a funnel as it climbs.

game/DustDevil.roc, lines 236-261

column_id : U64
column_id = 1

## The column: dust rising from a disc round the foot, carried along with
## the devil, spinning, lifting and flaring into a funnel as it climbs, all
## the more the stronger the devil is.
column : DustDevil.State -> Vocabulary.Emitter
column = |{ foot, travel, strength, lit, clock }| {
	..Emitter.default,
	id: column_id,
	seed: 41,
	position: { ..foot, y: 0.15 },
	rate: 190.0 * strength,
	lifetime: 3.0,
	start_size: 0.4,
	end_size: 1.6,
	start_colour: tint(lit, { shade: 1.0, alpha: 0.38 }),
	end_colour: tint(lit, { shade: 0.8, alpha: 0.0 }),
	velocity: { ..travel, y: 2.2 * strength + 0.4 },
	velocity_spread: spread({ across: 0.2, up: 0.6 }),
	acceleration: upward(0.5 * strength),
	spawn_radius: 0.45,
	swirl: 1.0 + 3.5 * strength,
	outward: 0.25 + 0.55 * strength,
	time_scale: clock,
}

Read it from the top:

  • ..Emitter.default is Roc's record update. The builder starts from Rocco's defaults and sets only what this source needs; a field it leaves out, such as drag or blend, keeps its default.
  • The literal numbers are the source's look: a three-second life, particles growing from 0.4 to 1.6 metres, fading to clear.
  • The State's values are the motion. As strength rises and falls, the column emits more dust, lifts harder, spins faster and flares wider. travel carries every particle along with the devil, so the dust stays round it as it wanders.
  • time_scale: clock is how the game's pause reaches Rocco's simulation. At 0 the whole whirl hangs still in the air, mid-spin.
  • id and seed let Rocco recognize the same source from one frame to the next, and keep its random sequence steady while it lives. The id is a named constant beside the builder, so the module's ids are easy to keep apart.

The skirt and the flecks are built the same way, with their own numbers: the skirt is big, faint puffs kicked out over a wide disc and slowed by drag; the flecks are small dark bits of grass flung up fast and falling back under a negative acceleration. tint, spread and upward are three small helpers in the module, so each colour and vector in a builder reads in one line:

game/DustDevil.roc, lines 205-229

## The dust's colour `lit`, each channel darkened by `shade` (1 leaves it
## as lit), at opacity `alpha`.
tint : Vocabulary.Rgb, { shade : F32, alpha : F32 } -> Vocabulary.Rgba
tint = |lit, { shade, alpha }| {
	r: lit.r * shade,
	g: lit.g * shade,
	b: lit.b * shade,
	a: alpha,
}

## A velocity spread as wide each way `across` the ground and `up` and down.
spread : { across : F32, up : F32 } -> Vocabulary.Vec3
spread = |{ across, up }| {
	x: across,
	y: up,
	z: across,
}

## An acceleration straight up by `lift` (a fall when it is negative).
upward : F32 -> Vocabulary.Vec3
upward = |lift| {
	x: 0.0,
	y: lift,
	z: 0.0,
}

How the Scene picks them up

The game's view in main.roc builds the Scene, and its emitters field joins every module's sources into one list. The devil's line hands it the walk as a Watcher. Its walking is false while the ride is paused or held, which is what sets the devil's clock to 0:

game/main.roc, lines 153-204, trimmed

view : Model -> Vocabulary.Scene
view = |model| {
		...
		# The dust devil's dust runs on the walk's clock: still while paused or
		# held. The Roost's smoke runs while held too, so a start inside (or
		# the loading screen's hold) shows it already risen; it starts as the
		# jeep turns into the lot, so it has risen by the doors.
		emitters: if (!model.switches.particles) []
		else List.join([
			if (outside) DustDevil.emitters({ walked: along, walking: model.walking == Walking and !model.held, eye: camera.eye, moment }) else [],
			if (interior and hall_shown and since_cut > smoke_lead) Roost.emitters({ smoke: model.ids.smoke, puff: model.ids.puff, clock: smoke_clock, seconds: model.seconds }) else [],
			if (interior and since_cut > smoke_lead) BackRoom.emitters({ smoke: model.ids.smoke, puff: model.ids.puff, clock: smoke_clock, seconds: model.seconds, since_cut, eye: camera.eye }) else [],
			if (Warm.warming(model.seconds, model.held)) [DustDevil.warm(camera.eye)] else [],

Each module that has particles adds one line here, and an empty list when it has nothing to show. The devil is only asked for its sources while the view is outside; the tavern's smoke has its own lines.

A source of your own

A campfire, a fountain or a chimney follows the same steps as the devil. Taking a campfire:

  1. Write the state first. Decide what your game knows that the fire depends on, and put it in a record of your own: where the fire stands, how high it burns, and the clock its particles run on. A function from your model to [Lit(Fire), Out] keeps the "nothing to show" case explicit, as Down does for the devil. None of this needs to mention Emitters.
  2. Write one builder per source. Start from ..Emitter.default and set only what the source needs. Put the look in literal numbers: flames that live half a second, grow and fade from orange to clear. Put the motion in the state's values: a rate and a rising velocity that follow how high the fire burns. Smoke above it is a second builder, with a longer life, a slow lift in acceleration and a little outward drift.
  3. Give each source an id and a seed. The id has to be unique among all the sources in the Scene: when two share one, the first wins. Named constants beside the builders, as column_id is, keep them in one place.
  4. Tie time_scale to your pause. Pass your game's clock through the state, 1 while running and 0 while paused, and every builder sets time_scale from it. A paused game then holds its particles still with no other code.
  5. Add the sources to the Scene's emitters. One line in view, joined with the rest, and an empty list when the fire is out. Once it leaves the list, its last particles drain away with their last settings.

Because the sources are values, the module can be tested with ordinary expects, with no renderer. The devil's tests check that it has no sources before it rises and three while it whirls, and that every source's time_scale is 0 when the walk is paused. When the module was split into its two halves, the new emitters was checked against the old at 3,400 moments along the walk, value for value, with == in a plain expect.

What made this pleasant

  • The engine's contract is one record type, documented where it is declared. The Emitter's doc comment says what every field means, its units and its limits. That was everything this module needed to know.
  • The pure-function style suits particles. The game holds no particle state at all, so there is nothing to keep in sync, save or reset. A pause is one field.
  • Testing is ordinary Roc, as above.
