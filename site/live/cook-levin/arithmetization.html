Chapter 30

Arithmetization

Arithmetization turns logic into arithmetic: NOT becomes 1 − x, and AND becomes a product. Add one identity, x² = x, and one step of the machine becomes four small polynomials, each variable to the first power at most, the kind that composes.

Logic says true or false; arithmetic can add, multiply and substitute, which is what composing six steps into one object needs. The stepper writes one step of the machine as polynomials, the first of the two ways to compose in “The program left unknown”: expand. Each bit of the state is a variable that is only ever 0 or 1, and logic becomes arithmetic:

  • NOT x is 1 - x;
  • x AND y is x·y;
  • x OR y is x + y - x·y.

On 0/1 values each of these gives 0 or 1, and the right one. Steve's 2023 stepper wrote them first, as three Python functions (stepper.py, lines 8 to 17):

def NOT(x):
    return 1 - x


def AND(x, y):
    return x * y


def OR(x, y):
    return (x + y) - (x * y)

In Roc (roc/Stepper.roc) the first and third read as they are written:

x² = x §

Every variable here is only ever 0 or 1, and on those values x² = x. A ring where every x² is x is a Boolean ring: every polynomial in it is multilinear, each variable to the first power at most. A monomial is then a set of variables, kept as a bit mask, and the product of two monomials is the union of their sets, the OR of their masks.

roc/BoolPoly.roc is that ring. Its product, with like terms summed in a table indexed by mask:

src/boolring.c is the C's version (0c233e3), with a 32-bit mask and checked int64 coefficients.

Two polynomials that agree on every 0/1 point reduce to the same multilinear polynomial, and a multilinear polynomial is fixed by its values on {0, 1}^n. So reducing by x² = x keeps every value the machine can see, and the canonical form makes == equality of functions (roc/BoolPoly.roc's header).

Steve's 2023 stepper built its four polynomials in the general ring, where x·x stays x²: there every product raises powers, x·x to x² and x²·x to x³, and keeps apart terms the machine sees as one, so one step's hb' has 786 terms where the Boolean ring's has 7. Composed in the general ring, the same six steps would need about 10^54 terms, of degree about 10 million, with step 2 alone over 10 GB (docs/DM_GENERAL.md), so that monstrosity is lost to history. In the Boolean ring each substitution keeps the polynomials multilinear, and “Six steps composed” composes all six in a fraction of a second.

One step §

The step reads the six bits of “The Boolean view”, the state's four and the instruction's two, and writes the state's four.

The construction names each fact about the state with an indicator, a polynomial that is 1 when the fact holds: AX is 0, the instruction is decr and the machine is still running, and so on. The new state is what any of the four instructions would make of the old one:

The stepper as a second machine §

Evaluated at the bits of a state and an instruction, the four polynomials give the next state's bits. So the stepper is a second implementation of the machine, written as algebra.

Theorem 11. On every one of the 4,096 programs and each of the four inputs, the stepper, evaluating the step polynomials one step at a time, accepts exactly when run_progam does.

Proof. Run all 16,384 pairs both ways, on the step polynomials as Steve's stepper.py builds them, which src/stepper.c rebuilds term for term: the two agree on every pair, and 5,596 pairs accept.

The check began as Steve's. His test_with_stepper runs a program through the step polynomials, each step evaluating them at the state's 0s and 1s (stepper.py, lines 147 to 158):

def test_with_stepper(program, ax):
    AX = ax
    halted = False
    accepted = False
    for cmd in program:
        (AX, halted, accepted) = step(
            AX=AX,
            halted=halted,
            accepted=accepted,
            op=OPS[cmd],
        )
    return accepted

Then find_solutions asserts, after running all 4,096 programs on the interpreter, that every formal language has a program and that each one's example program, run through the polynomials on each input, accepts exactly its inputs (virtual_machine.py, lines 159 to 160 and 178 to 180), 16 programs on 4 inputs:

    for y in range(16):
        assert len(solutions[y]) > 0

        for i in range(4):
            accepted = stepper.test_with_stepper(example_program, i)
            assert accepted == (i in lang)
