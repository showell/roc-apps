Chapter 22

The Cook-Levin machine

Circuit design, then complexity theory. The machine in a new form, run backwards; it needs “The circuit, in full”. We run the circuit backwards, the move at the heart of Cook-Levin: fix the answer, leave the program unknown, and ask which programs fit.

The decider of “The circuit, in full” is a checker: hand it a problem and a program, and it says true or false. Cook and Levin's idea is to run a checker backwards. Fix the problem, leave the program unknown, pin the output to true, and ask which programs fit. The circuit does the same work as before; only the question changes. Every form so far took a program and gave a verdict; this one takes the verdict and asks for the program, the direction a search for certificates needs.

The circuit, turned around §

The want register is fixed at the problem's bits. The program register becomes twelve unknown wires, v1 to v12. The output wire is required to be 1. Everything in between is the same 24 steppers and four comparators, and every wire in them is now an unknown too, tied to the wires feeding it by the rule of its gate.

A setting of the twelve unknowns that satisfies every gate's rule and lights the output is a program that decides the problem. The circuit has a satisfying setting exactly when some program decides the problem.

The frame switches here from circuit design to complexity theory.

The tableau §

Cook's proof draws the run of a checking machine as a grid, the tableau: one row for each moment of the run, each row the machine's whole state, and each row fixed by the row above it through a small local rule. Here the grid has seven rows, the start and the six steps, and four columns, one per core. Each cell is a state of four bits, hb, lb, halted and accepted. The top row is known, since core i starts with AX = i and both flags 0, and each cell below it is one stepper applied to the cell above and to that row's line of the unknown program. The local rule is the stepper, drawn from its parts in “The machine as a circuit”.

For a general checker the grid is as wide as its tape and as tall as its running time, and when the time is polynomial in the input's length, the grid and its rules are polynomial in size too. That is the whole of the theorem's construction: any question a fast checker can answer becomes the question of whether such a grid can be filled in consistently.

The gates, counted §

The stepper's gates as the SAT encoding builds them, in sat_step (src/sat.c): 34 AND and OR gates.

tests/test_sat.c holds these gates to the machine's step on all 64 settings of the stepper's six input wires. The whole circuit comes to 404 gates over the 12 unknown program bits, fewer than 24 steppers' 816, for the reasons “Appendix: the step's encodings” gives.

The tableau is still empty here; filling it in, for one program and then for all of them, comes next.
