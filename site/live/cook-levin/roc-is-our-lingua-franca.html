Chapter 3

Roc is our lingua franca

Ordinary computation. Tools and history; it needs “The machine”. Here is which programming language does which job in this book, and why Roc does most of them.

Roc is our lingua franca in this book. This is not a book about type systems, but Roc's clear type annotations help us express mathematical concepts. It's also simply a good working language. It has the horsepower for computation and versatility to live in the browser. The Roc port composes all six steps of the machine into four polynomials and checks them at every point (“The Roc port”), and the app that builds this book is Roc as well.

Nibble and Nibble++ are Steve's toy languages. They are specifically designed to be small in scope. Nibble fits in your hand. Nibble++ pushes just past brute force. Both come to life in playgrounds that accompany the book, and the machine you click there is the same Roc code this book quotes, compiled to run in your browser. The pinned Roc builds each page's machine as a small wasm module, linked with a C host of 107 lines, web/platform/host.c, which holds the allocator. Try Nibble's puzzles and the Nibble++ playground.

Python is the programming language that inspired the book. We use Python mostly as a historical relic, but it remains an oracle to Roc and occasionally shines as a mainstream programming language whose syntax most programmers understand. Steve's 2023 Python, virtual_machine.py, poly.py and stepper.py, is where the machine and its polynomials began, and its report is still the golden file that the C and the Roc print byte for byte.

C is our utility infielder. We use it for its raw speed and easy linkability. And when rocsat says no program exists, it's a small C program that checks the proof, so the book never has to take Roc's word for Roc's answers. That program is src/drat.c, the book's own DRAT checker, which replays each of rocsat's proofs lemma by lemma (“The solver's work, in full”).

Finally, JS does what JS does best. JS runs the skin of our toys. It also serves as a final oracle: the same machine, written in plain JavaScript, gives the same answers in the book's last chapter, and runs there on a compiler we happen to have written ourselves (in Roc!). That program, js/cook_levin.js, prints the same report and composition byte for byte under node and as an x86-64 program from js-x86 (“What comes next”).
