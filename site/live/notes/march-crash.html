A March crash, fixed by November

In March 2026 Steve wrote a small Roc program by hand. One new record field made the compiler panic. In November he came back to it. Today's compiler builds it and runs it.

The program

zulip-roc is a small in-memory database shaped like Zulip's. It holds channels, messages and topics, each in a Dict keyed by ID. Its app builds four databases and prints each one with dbg.

The crash

On March 15 Steve added a User type and a user_map field. Nothing inserts into it yet, so its Dict stays empty.

User: {
    user_id: ID,
    full_name: Str,
}

Database : {
    channel_map : Dict ID Channel,
    message_map : Dict ID Message,
    topic_map : Dict ID Topic,
    user_map : Dict ID User,
}

new : Database
new = {
    channel_map: Dict.empty({}),
    message_map: Dict.empty({}),
    topic_map: Dict.empty({}),
    user_map: Dict.empty({}),
}

From DbTypes.roc and Database.roc, March 2026, in the old syntax.

With that field the app stopped building. The compiler of the day, the old one written in Rust (a nightly from September 2025), panicked:

thread 'main' panicked at crates/compiler/gen_llvm/src/llvm/build.rs:5582:19:
Error in alias analysis: error in module ModName("UserApp"),
function definition FuncName(...), definition of value binding ValueId(11):
could not find func in module ModName("UserApp") with name FuncName(...)

The commit before it, without the field, built and ran. The likely cause: the function that prints a User was never generated. No User exists anywhere except inside an empty Dict that dbg prints.

What changed

In November Steve closed the loop. The code needed small changes for Roc's new syntax, and the logic stayed the same, user_map included. Claude, an AI coding agent, made the port under Steve's supervision. Here are the same types now:

DbTypes := [].{
	...
	User : {
		user_id : DbTypes.ID,
		full_name : Str,
	}
}

Database := [].{
	Database : {
		channel_map : Dict(DbTypes.ID, DbTypes.Channel),
		message_map : Dict(DbTypes.ID, DbTypes.Message),
		topic_map : Dict(DbTypes.ID, DbTypes.Topic),
		user_map : Dict(DbTypes.ID, DbTypes.User),
	}

	new : Database.Database
	new = {
		channel_map: Dict.empty(),
		message_map: Dict.empty(),
		topic_map: Dict.empty(),
		user_map: Dict.empty(),
	}
	...
}

From DbTypes.roc and Database.roc, November 2026.

Each module is now a type module, Name := [].{ ... }, and its types are named through it. Type arguments take parentheses: Dict(ID, Channel). Dict.empty() takes no argument.

A record update is { ..r, f: v }, and a block takes braces. The port calls functions directly where the old code used |>:

insert_channel : Database, Channel -> Database
insert_channel = |database, channel|
    channel_id = channel.channel_id
    new_map = Dict.insert(database.channel_map, channel_id, channel)
    { database & channel_map: new_map }
insert_channel : Database.Database, DbTypes.Channel -> Database.Database
insert_channel = |database, channel| {
	channel_id = channel.channel_id
	new_map = Dict.insert(database.channel_map, channel_id, channel)
	{ ..database, channel_map: new_map }
}

insert_channel in Database.roc, March, then November.

db |> Database.insert_channel(channel)
Database.insert_channel(db, channel)

A call in ZulipGlue.roc, March, then November.

The rest is just as small: when became match, List.walk became List.fold, and numbers print with U32.to_str.
