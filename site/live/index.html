Steve's Roc Work

Steve Howell wrote or refined these Roc apps, this book and these packages through agentic development, with Claude, an AI agent, writing the code. The apps run here in your browser, compiled to WebAssembly.

Everything on this page is open source under the Universal Permissive License (UPL) 1.0, the license Roc itself uses.

roc-chat

A live chat at chat.lynrummy.com for a small group of humans and their agents. It has channels with topics, direct messages, Markdown with images, live updates, search, reactions, edits and quote-replies. You sign in with a password, with GitHub, or with a code from a device already signed in. Agents get keys of their own, and read and post like members. The chat replaced the group's earlier one, written in Zig. It matched that chat's behavior first, then changed or left out a few things on purpose.

Roc at workIts main security boundaries are types, so the compiler catches an unescaped string or a post from someone not signed in. A request's path and a form's fields arrive as an UnvalidatedString. Most ways out of it run a check and return a checked type, such as a Name or a Topic. A message's Markdown leaves by another way: once it is known not to be blank, it comes out as a plain string, which roc-markdown escapes as it renders it. Markup reaches a page only as TrustedHtml. An action that needs a signed-in user takes a SignedIn. TrustedHtml and SignedIn each have one unchecked door, named to stand out: dangerously_trust and dangerously_assume.

check : {
    acting : SignedIn,
    place : Place,
    directory : Directory,
    act : Access.Act,
} -> Try({}, [NotAMember, ScopeOff])

From app/Access.roc: the check for who may read or post. It takes a SignedIn, never a bare user.

Roc decides routing, who may read and post where, and what gets saved, and it builds every page. roc-markdown renders each message, escaping its text. roc-syntax-color colors its code blocks in four languages. Both are Roc packages, with their own cards below. Most modules are pure. A module's expects, Roc's inline tests, sit at its foot or in its spec module.

Roc plays nice with othersRoc leaves the outside world to a platform. roc-chat has its own, with a host in Zig. The host does the network, the disk, the clock, random bytes and crypto. Two secrets stay in the host: the key that signs sessions and GitHub's client secret. The Roc code never sees them. The host reports facts, such as whether a signature matches, and the app decides what they mean.

The file system is the database. Users, channels, transcripts and reactions are plain files in one folder, readable with cat. FileFacts is the only Roc module that touches them.

Live updates are Server-Sent Events. Steve chose them because they are "the right tool for the job". Each live page holds one plain HTTP stream, which reconnects by itself. After a reconnect, a conversation's stream catches up on what the page missed. Everything you send goes up as an ordinary request.

The pages are HTML built in Roc. JavaScript files send what you type and run the live parts. The server sends no stylesheet; the scripts carry the styles.

Search's index is in Zig. The host keeps it in memory, for speed, and the app decides who may search what. One lock lets only one Roc call run at a time. The host reads and writes the network outside the lock. A password check or a GitHub sign-in lets go of the lock while it works, so another Roc call can run.

A hosted function is a Zig function that Roc calls for an effect. A test holds each one to the layout that Roc's glue tool reports, field by field and tag by tag. Two swapped fields fail the build's tests.

Safari Ride

A drive through the country, as a screensaver: hills, a winding road, herds, and a rider who leans into the turns. It has lineage in TypeScript, where it began, and this Roc version is its latest rewrite. Space pauses, the arrows step through the ride, J jumps to the next intersection, R starts over.

Roc at workSafari Ride models a whole world with Roc's types. On each stretch of road a cat crosses, a bird flies over, or the road is quiet: three cases of one tag union, and the compiler checks that every match handles them all. A step of the ride answers [Continued(Tour), Restarted(Tour)], a union declared nowhere but in its function's signature. And every instant of the ride is a plain value, so stepping backward is just returning to an earlier one.

encounter_throttle : Encounter, Animation.Stage -> ThrottleLimit
encounter_throttle = |encounter, stage|
    match encounter {
        CatCrosses(_) =>
            match stage {
                Playing(_) => AtMost(Acceleration.steady)
                Waiting | Past(_) => NoLimit
            }
        BirdHere(_) | QuietRoad => NoLimit
    }

From canvas_apps/safari/EncounterReaction.roc: while a cat crosses, the rider eases off.

Roc plays nice with othersThe ride came to Roc from TypeScript. In your browser it's a wasm module holding the Roc ride and a small Zig host, and the page's JavaScript calls that host to step the ride and fetch each frame to paint.

roc-markdown

A finished, complete package, built to a professional standard and in production: a markdown renderer for chat, safe to show whatever a user typed. Each render carries a budget for its work, an ordinary value, so a message built to overload it is refused before it's shown. It renders every message in roc-chat at chat.lynrummy.com, and the playground runs it live.

Roc at workIn Roc only a platform can perform effects, and a package has none, so a renderer fed hostile input can't touch the disk or the network. The same pure functions render chat on a server and, compiled to WebAssembly, in your browser as you type.

Roc plays nice with othersroc-markdown began as a port of the chat's original renderer, which was written in Zig. In the playground, a small Zig host and a little JavaScript call the same Roc functions that the chat server runs.

roc-syntax-color

A Roc package that colors source code for web pages, in seven languages: Roc, JavaScript, Shale, Zig, C, Odin and Python. Code goes in and HTML comes out, with a span around each comment, string, number, keyword, name and type, and your stylesheet picks the colors. Any text at all comes out colored, even half a program or a string left open. It colors the code in the Safari book and the books book.

page_code : Str -> Str
page_code = |code| "<pre><code>${SyntaxColor.html(SyntaxColor.roc, code)}</code></pre>"

From the package's README: a page's code block, colored.

Roc at workThe package is pure functions from Str to Str, with no platform of its own, so any Roc app on any platform can import it. Each language is a lexer of its own, and each lexer covers every byte of its text exactly once, in order, so the HTML with its tags removed is exactly the escaped input.

Roc plays nice with othersIts checks hold it to real files in all seven languages, from git's first commit to CPython's standard library, each colored byte for byte as recorded. Its Odin lexer follows Odin's own tokenizer, and its Python lexer the language reference's chapter on lexical analysis.

BASIC

Written directly in Roc, not translated from another language, it runs two dialects, ECMA-55 Minimal BASIC and the BASIC of the 1978 Creative Computing games, and it's graded against the National Bureau of Standards' test programs and the classic games. The REPL runs here; the same interpreter runs as a command-line program.

Roc at workIn Roc a value never changes, yet this interpreter updates its machine in place. Roc reuses a value's memory whenever nothing else refers to it, and the machine is designed so that nothing else does. A check measures what each loop of the interpreter's small test programs allocates, and most of them allocate nothing at all.

Roc plays nice with othersThe 1978 games are graded against runs of basic101, a BASIC interpreter written in Ruby, so this one reproduces Ruby's random numbers, the Mersenne Twister behind Random.new(0), and a game that calls RND grades byte for byte. The REPL runs on a small Zig host with a JavaScript page.

Fast Track

The marble race board game: you play red against three computer players, and their marbles walk the board as they move. Each computer player plans its whole turn before it moves. It tries every line of play for the rest of the turn, up to five plays deep, and it counts a position reached two different ways only once. It scores where each line would leave the board, by Steve's own ranking of the board's squares, a bonus for each step a marble takes down its home stretch, and the aces, jokers and jacks it's holding back for later, and then it plays the best line. It never sees a card it hasn't drawn. Its weights were settled by racing each candidate against the reigning champion over thousands of dealt games. The rules and the whole page are Roc, ported from Steve's Elm version; the computer players are new, written by Claude.

Roc at workThe game's rules are one pure Roc function, and the search simply calls it to see where each line of play leads. Every game state is a value, so trying a line never disturbs the real game, and no move ever has to be undone.

Roc plays nice with othersThe game is a port of Steve's Elm version, and it reproduces Elm's random number generator to the bit, even the rounding that Elm's compiled JavaScript does, so a seed deals the same cards in both and a game replays move for move. A small Zig host runs the wasm, and a little JavaScript draws what Roc answers.

Dog Park

A herding game: press a dog to leash it, drag it through a park full of critters, and herd all the cows into one bunch. Dogs of its breed follow it in herds and chains, cows run from a moving dog and drift toward each other, goats walk boldly up to the dogs, and chickens wander out to eat the trail of poop the herds leave. The world wraps around, top to bottom and side to side. Your park is kept in your browser, so it's where you left it when you come back.

Each time the leashed dog moves a pixel, the park is walked outward from it, one critter at a time, shortest link first: Prim's algorithm, growing a minimum spanning tree through the herd, up to 48 critters a pixel. A critter reacts only to the critters that have already moved this pixel, so a tug on the leash ripples down a chain of dogs.

Roc at workRoc is the game's configuration language, and more. The Zig platform does the heavy lifting of the park: the board, who stands where, the bookkeeping of every step. Everything that makes it this game is Roc: the world and its levels, where each critter starts, what each kind does about the others (Ignore, Keep, Herd or Close, a match the compiler holds to every pair of kinds), what the cows say when you press them, and the park's colours. A new kind of critter is a change to the Roc alone.

Roc plays nice with othersA Zig board keeps the books and calls the Roc, the two compiled together to WebAssembly and run sixteen times a second. A plain Zig version of the walk, sharing none of the Roc's code, checks every step the Roc takes in the tests.

Seattle Delivery

A delivery planner you can watch at work: eight trucks deliver a hundred grocery orders across a not-to-scale map of Seattle. Each shift starts as one cluster of orders per neighborhood. Clarke and Wright's savings method merges them: of every pair of routes, it joins the two whose joining saves the most, and repeats while a join saves anything, then brings the routes down to the eight trucks. Local search follows: reversing a run of stops, moving a stop to another truck, trading stops between trucks, and handing a few of a neighborhood's houses to a second truck that passes by. Every move is judged by one whole-number cost, which charges each minute of driving more for every tote still aboard, so a truck wants to drop its heaviest loads early. The whole solve runs four ways, two ways of splitting a load too big for one truck by two ways of treating Medina, and the cheapest plan wins.

Press space to play the day, S to shuffle up a new shift, and A to step through the solver itself, one move at a time, as it builds the plan. There's no score and nothing to win; the fun is watching the routes make sense.

Roc at workThe whole planner is one pure function, a day's orders in and a dispatch plan out, which the browser and the test harness each run under their own small Zig host; it can't tell which. Being pure, it's reproducible to the bit: native and WebAssembly agree on every route of twenty recorded shifts. The code reads as plain values in and out, and Roc updates a route in place whenever nothing else holds it, which is most of how it runs within about 1.3 times the Zig it replaced.

Roc plays nice with othersThe solver is Roc compiled to WebAssembly, and the original TypeScript still draws the map and the trucks from the plan it answers. It replaced a Zig solver, and matches the TypeScript reference it was ported from, every route and every replay frame.

Knight's Tour

A knight visits all 64 squares of a chessboard, landing on each exactly once. Click a square and a depth-first search starts there. Knights pile on, hit dead ends, and are pulled back off. Play, step, rewind and a speed slider let you watch the search think, in both directions. Steve's original was hand-written in CoffeeScript circa 2011. This Roc version is a port of a later one in Zig.

The search tries each knight's moves fewest onward moves first. It finishes from every start square: in 64 moves from b2, with no backtracking, and in 2,520,884 from g6.

Roc at workThe search speaks only by adding moves to an event tape, one byte a move. The board you see is a cursor walking that tape, so a step back undoes one move, and rewinding falls out of the data. A red square, where a knight was placed and then pulled off, comes from the board alone, so it is right at any point on the tape.

Move : [Place(U8), Remove(U8), RemoveAndGiveUp(U8), GiveUp]

From canvas_apps/chess_kit/Tape.roc: everything a search can say.

Roc plays nice with othersThe search and the board are Roc, compiled to WebAssembly with the canvas apps' small Zig host. A little JavaScript keeps the clock, the keys and the pointer, and paints each frame the Roc answers.

Eight Queens

Eight queens on a chessboard, none attacking another. Click a square to pin the first queen there. The search fills the other seven rows, one queen a row, and backs up when a row has no safe column. Every square is on some solution, so every pin finds one. Steve's original was hand-written in CoffeeScript circa 2011. This Roc version is a port of a later one in Zig, and runs on the same event tape as the Knight's Tour.

Roc at workThe whole puzzle also fits in two lines of Roc. They work breadth-first: each step of the fold extends every board with every safe column, so nothing ever backtracks, unlike the search you watch. A column is safe when no queen shares it and no queen is as many columns away as it is rows. The two lines find all 92 solutions, the first [0, 4, 7, 5, 2, 6, 1, 3].

r = [0, 1, 2, 3, 4, 5, 6, 7]
all = r.fold([[]], |bs, _| bs.join_map(|b| r.keep_if(|c| b.map_with_index(|q, i| q != c and (if q > c q - c else c - q) != b.len() - i).all(|ok| ok)).map(|c| b.append(c))))

Steve's golf: every solution, one row at a time.

Luke's examples

roc-ray is Luke Boswell's Roc platform for 2D games, visual tools and interactive apps, powered by raylib, and it runs natively on macOS, Linux and Windows. These six toy retro games are roc-ray's own examples, all written by Luke, © 2024 Luke Boswell under the UPL. What this site adds is a proof of concept: Luke's apps also run as web pages, which is what you see here. They show the power of Roc in miniature.

Roc at workLuke's game rules are pure functions, a world in and the next world out: their signatures use ->, not =>, so the compiler guarantees they do no I/O. So the rules moved to the browser with their arithmetic untouched, changing only import lines and a file name or two. Claude adapted the rest for the browser, a light modification: the drawing was rewritten, from roc-ray's drawing calls to a frame described as a value, and each ported file says in its own comment what changed and why. The same files still type-check against roc-ray.

Roc plays nice with othersroc-ray's host is Zig over raylib, a C library. In the browser, the same rules run on a Zig wasm host, and JavaScript draws on a canvas.

roc-screensaver

A Roc platform written in Zig, whose own software rasterizer paints each frame with no GPU and no graphics library, so one Roc app is both a Windows screensaver and a web page. The web page is the developer's quick preview: a wasm platform paints the same shapes on a canvas, so a change shows in a browser in seconds, long before a Windows machine is involved, and the repo's checks hold the page's frames to the native ones. Three screensavers run on it: Lanterns, a sunrise made for Roc's 0.1.0 launch; Tides, bands of water under a sky that goes from dawn to night; and Bubbles, which rise, wobble, and fade or pop. The Windows build passes headless on GitHub's Windows runners, and runs on a real Windows machine.

Even if you don't intend to build a screensaver, the repo is instructive for Roc newcomers. It shows how a Roc app runs on more than one platform, and its lib/ has helpers (shapes, brushes, colors, lettering, keyboard input) for building things like game engines.

Roc at workAn app is one Roc value: a model, a step from one model to the next, and the shapes each model looks like. Only the platform changes between Windows and the browser, and the keyboard controls belong to the app, in Roc, so they work the same in both.

Roc plays nice with othersOn Windows a Zig host steps the app, reads each frame out of Roc's memory, rasterizes it and hands it to the window through GDI. In the browser a small Zig wasm host and a little JavaScript paint the same shapes on a canvas.
