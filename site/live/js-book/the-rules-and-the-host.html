Chapter 7

The rules and the host

This chapter covers the rest of the parts around the loop: the two modules every run shares, the host that carries the effects, and the page.

ValueRules and Events §

Two modules serve everything that runs a program.

ValueRules holds JavaScript's rules for values: property reads and writes, operators on mixed values, the methods of strings, arrays, Maps and Sets, and the errors they throw, each message in one place. The VM's fast paths settle the common cases (numbers, an object's own property, an array's item) and hand the rest to a rule. A rule takes a small machine of the cells and the run's status, ValueRules.Machine: the VM lends it the cells and takes back what the rule gives, so the cells have one owner while the rule writes them. The module was split out of the walker when the VM borrowed it (d8d6b7fe), and for a while both engines used it.

Events holds the queue of callbacks and its virtual clock (b69660c4). A timer's callback, a click, the canvas's next frame(t) and a collection onCollect hears are each an event, due at a time in milliseconds, run earliest first, and two at one time in the order they were queued. The clock reads 0 while the program runs and moves to each callback's time as it runs, so a program's output is the same on every run and the same as node's.

The host and its effects §

The interpreter reaches the world through a host, Canvas.Host, a record of four effectful functions:

An effect happens when the program calls for it: the VM hands each one to emit! in program order, console.log included, so a program that stops halfway has drawn what it drew before the stop. A read, pointer! or key!, is asked of the host when the program asks. collected! hears of each collection once it has swept. Every effect has one written form, Canvas.line_of, so a sample's golden log is the very text the page paints from.

  • The page's host (JsApp.roc, on the platform in js/wasm/) calls into the page's JavaScript while the Roc call runs.
  • The recording host, js-canvas (JsCanvas.roc), writes every effect and every read as a line, for the golden logs.
  • js-vm's host prints each log as it is made.

The page §

The page is js/web/. js_page.js makes everything the page shows, its styles included, so the HTML is only a door: an editor, the canvas and the console. js_runner.js loads js.wasm, starts a program, then calls it a frame at a time, about 30 times a second, each frame a tick of the program's clock (Vm.tick!) that runs the clicks queued since the last tick, the timers due and frame(t). js_painter.js paints each effect's line on a 2D canvas as it arrives, and the browser shows the canvas when the frame's call returns.

The memory view, js_memory.js, is a popup with two small charts of the last run. The top one is the heap's cells in use, which climb as the program allocates and drop at each collection, a sawtooth; the bottom one is the wasm memory's size. The VM reports each collection through collected!, so the count lives in the host, outside the machine.

js/build.shale names every file but index.html by its bytes, so a browser always loads the scripts that match its page, and it replaces the page only after js/page_check.mjs passes.
