Chapter 6

The fib race

x86/race/fib_race.js computes F(740000) with the ordinary iterative algorithm. Its numbers are arrays of base-10^7 limbs, added one into the other in place. This race is where the compiler was tuned, so its record shows which changes paid and by how much. Three contestants run it, one after another, each timed from outside as its whole process (shale x86/race.shale):

contestant what runs
js-x86 this repository's compiler, writing every byte of the executable from Roc
node the same source
Roc x86/race/fibonacci_race.roc, the same algorithm line for line, with U64 limbs, built with --opt=speed, which hands the code to LLVM

Each one's whole output, more than 150,000 digits, is held to a stored sha256 of the answer. The rules are fixed: the algorithm stays the ordinary one, node runs the same source, and any trick in the compiler has to be one that would help other programs too.

The ordinary algorithm is the slow one on purpose. Fast doubling, which takes F(2k) and F(2k + 1) from F(k) and F(k + 1), reaches F(740000) in about 20 steps of a few big multiplications each, where the race makes 740,000 big additions, and with a good multiplication it finishes in a fraction of a second. The race keeps the additions because its subject is the compiler: one hot loop of array reads, additions, a carry and array writes, the shape of code every program here leans on, run long enough to time well.

Where it stood on 2026-11-26 §

The median of three runs each on 2026-11-26, at master 62cb716 and a load of 0.3 to 1.0 (x86/RACES.md):

contestant time
js-x86 50.37 s 0.63 of node's time
Roc, LLVM 51.66 s js-x86 takes 0.98 of it
node 79.73 s

Runs on this box move by about a tenth, so within that spread js-x86 and LLVM's Roc are even, and both beat node by about a third. An earlier single run that day, at a load of 0.88, read 55.75 s, 56.42 s and 75.80 s (x86/race/README.md, after 8989013).

What the loop costs §

The race lives in one loop, addInto's, one limb a time round. What closed the gap to Roc were the fixes that x86/race/README.md numbers 1 to 19, every one a general rule with its own test. Among them: an array's length and items read in line, a comparison fused with its jump, a select of two numbers made with a conditional move, which ended the carry's mispredicted branch, and a loop's carried values kept in registers first. The table below starts just before the last two, fixes 18 and 19. After them came the integer counter, the largest lead the race's README ranked: a loop counter that the compiler proves whole and in range is kept as an integer, so it steps with one add and indexes the array directly, where a double needs a conversion first. Counted with objdump on 2026-11-26 (x86/race/README.md):

one limb of addInto's loop instructions
Roc, LLVM 46 to 51
js-x86 at c990f68 76
js-x86 after fixes 18 and 19 71
js-x86 with the integer counter 64

Of js-x86's 76, about 25 came from the numbers being JavaScript doubles: moves between the general and the floating-point registers, conversions to whole numbers for indexing, and unboxing an array's address. Roc pays for its own representation in turn: its U64 arithmetic is checked, three overflow branches a limb, and each list write tests the list's reference count first. The README's other leads, constants kept for the loop and an array's address reused, are open.

The other races §

Four more races time the compiler against node:

  • the bank race makes 110 million transfers between 500 accounts, each an instance of a class kept in an object keyed by name (x86/bank/README.md);
  • the fourteen race runs a tiny machine of 14 bits, written as one function, over all 16,384 inputs for 21,000 rounds (x86/fourteen/README.md);
  • the SAT race runs rocsat, a SAT solver written in Roc, carried line for line into the subset: its CDCL search, conflict-driven clause learning, the algorithm of modern SAT solvers, over a fixed workload of instances (x86/satrace/README.md);
  • big daddy, from “The compiler to x86-64”, runs a day in a small city per round, every feature of the subset at once (x86/bigdaddy/README.md).

x86/RACES.md keeps every race's latest verdict, each the median of three runs on a quiet box, timed from outside. The Roc column is each race's port to Roc, built by LLVM, and for the SAT race rocsat itself:

race js-x86's time over node's over Roc's run
bank ledger, 110 million transfers 1.69 0.86 2026-11-26, 62cb716
fourteen, 21,000 rounds 1.40 1.72 2026-11-26, 2f6f510
SAT, the race workload 1.95 2.52, rocsat 2026-11-28, e5babdd
big daddy, 15,000 rounds 1.56 - 2026-11-28, e5babdd

The bank and fourteen races are object and call heavy, where node's hidden classes and inlining pay. The SAT race's ratio was 2.29 the day before, and “What the compiler leaves to an optimizer” says what moved it. Big daddy has run at its full size since the collector (05a7757). It prints a distance in whole hundredths where program 54 prints a fraction, since the executables print only whole numbers so far, and its executable prints node's output byte for byte. Each race's README has the runs that led to these.
