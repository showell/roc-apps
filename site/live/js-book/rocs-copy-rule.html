Chapter 5

Roc's copy rule

Both programs lean on one rule of Roc's. The interpreter keeps a JavaScript program's heap in one Roc list, which many of its instructions write; the compiler builds an executable's bytes by appending to one list. Each is fast only while Roc writes its list in place, and this chapter states when Roc does. “Handing the machine on” gives the three habits the interpreter took from it.

When a write copies §

Roc writes a list in place only while the list has a single owner, and a copy is silent. On RC1 every copy is a use after a consume: a write (List.set, append, Dict.insert) takes the value, and something still reads the old one after it. The copy allocates the whole list again on every such write, so its cost grows with the list.

Each shape below is a loop in roc-apps' tools/copy_shapes/CopyShapes.roc, held to its count of allocations a write in the release and dev builds (expected.txt and expected-dev.txt beside it, measured on RC1). The listings are lines of those loops, each loop's call of itself written on one line; each copying shape sits beside its twin that writes in place.

Records and boxes §

A record update copies the record around the field it writes, inline sub-records included. A Box carried untouched is free, but every write re-boxes it, one allocation a write. “Handing the machine on” shows both at work on the interpreter's machine record.
