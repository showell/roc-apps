A dust devil in Rocco: building with Emitters

Steve has used Claude to build a small app with Rocco, Braeden Foster's 3D engine for games written in Roc. The app is Safari Walk, a ride down a savanna road at sunset (its source). Steve is happy to report that the package provides lots of functionality with almost no pitfalls. He mostly directs Claude to build things out, and wears the "movie director" hat more than the "quality assurance" hat. The code on this page shows a typical module that exploits a key feature of Rocco, the Emitter paradigm.

The module is game/DustDevil.roc. As the ride goes on, a whirl of dust rises on the verge, wanders across the road in the low sun, flinging bits of grass round in it, and falls apart behind the jeep. Every snippet below is quoted from safari-walk at commit , or from Rocco at commit , the engine that commit builds on, with a link to its lines.

The Emitter paradigm

A Rocco game is a Roc app: a model and a few pure functions. Each frame, its view returns a Scene, a plain value that lists the camera, the lights, the meshes and, in a field called emitters, the particle sources. The game never moves a particle. An Emitter is a record that describes a source as it is now: where it is, how many particles a second it emits, how long they live, how they grow, change colour, drift and spin. Rocco's host simulates every particle from that description.

Two consequences shape everything below. When a source's settings change from one frame to the next, the particles already in the air follow the new settings. When a source leaves the list, it stops emitting, and its particles drain away with their last settings. So a whole dust devil can be a pure function from how far the walk has come to a short list of records. The record's doc comment is the engine's whole contract for it:

Rocco also gives Emitter.default, a stationary, soft, round source whose doc says to set an id and a rate before use. Every builder below starts from it.

One builder, whole

The column is the main body of the devil: dust rising from a disc round the foot, spinning, lifting and flaring into a funnel as it climbs.

Read it from the top:

  • ..Emitter.default is Roc's record update. The builder starts from Rocco's defaults and sets only what this source needs; a field it leaves out, such as drag or blend, keeps its default.
  • The literal numbers are the source's look: a three-second life, particles growing from 0.4 to 1.6 metres, fading to clear.
  • The State's values are the motion. As strength rises and falls, the column emits more dust, lifts harder, spins faster and flares wider. travel carries every particle along with the devil, so the dust stays round it as it wanders.
  • time_scale: clock is how the game's pause reaches Rocco's simulation. At 0 the whole whirl hangs still in the air, mid-spin.
  • id and seed let Rocco recognize the same source from one frame to the next, and keep its random sequence steady while it lives. The id is a named constant beside the builder, so the module's ids are easy to keep apart.

How the Scene picks them up

The game's view in main.roc builds the Scene, and its emitters field joins every module's sources into one list. The devil's line hands it the walk as a Watcher. Its walking is true only while the walk's clock runs and the ride isn't held, so a pause or a hold is what sets the devil's clock to 0:

Each module that has particles adds one line here, and an empty list when it has nothing to show. The devil is only asked for its sources while the view is outside; the campfire and the tavern's smoke have their own lines. On the step after a jump to a chapter, model.fresh is set and the list is cleared_sources instead: a source for every id the walk uses, each emitting nothing and with a lifetime shorter than the step, so every particle left from where the walk was dies at once, and the real sources rise anew on the next step.

A source of your own

A campfire, a fountain or a chimney follows the same steps as the devil. The walk's own campfire, in game/Campfire.roc, is built that way, in the same two halves. Taking a campfire:

  1. Write the state first. Decide what your game knows that the fire depends on, and put it in a record of your own: where the fire stands, how high it burns, and the clock its particles run on. A function from your model to [Lit(Fire), Out] keeps the "nothing to show" case explicit, as Down does for the devil. None of this needs to mention Emitters.
  2. Write one builder per source. Start from ..Emitter.default and set only what the source needs. Put the look in literal numbers: flames that live half a second, grow and fade from orange to clear. Put the motion in the state's values: a rate and a rising velocity that follow how high the fire burns. Smoke above it is a second builder, with a longer life, a slow lift in acceleration and a little outward drift.
  3. Give each source an id and a seed. The id has to be unique among all the sources in the Scene: when two share one, the first wins. Named constants beside the builders, as column_id is, keep them in one place.
  4. Tie time_scale to your pause. Pass your game's clock through the state, 1 while running and 0 while paused, and every builder sets time_scale from it. A paused game then holds its particles still with no other code.
  5. Add the sources to the Scene's emitters. One line in view, joined with the rest, and an empty list when the fire is out. Once it leaves the list, its last particles drain away with their last settings.

Because the sources are values, the module can be tested with ordinary expects, with no renderer. The devil's tests check that it has no sources before it rises and three while it whirls, and that every source's time_scale is 0 when the walk is paused. When the module was split into its two halves, the new emitters was checked against the old at 3,400 moments along the walk, value for value, with == in a plain expect.

What made this pleasant

  • The engine's contract is one record type, documented where it is declared. The Emitter's doc comment says what every field means, its units and its limits. That was everything this module needed to know.
  • The pure-function style suits particles. The game holds no particle state at all, so there is nothing to keep in sync, save or reset. A pause is one field.
  • Testing is ordinary Roc, as above.

A note on the fields

Five of the fields used here (acceleration, spawn_radius, swirl, outward and time_scale) come from Steve's fork of Rocco, github.com/showell/rocco-engine, which added them for outdoor effects like this one. The rest is Rocco as Braeden wrote it. Steve likes to hold his own forks of projects sometimes while sending work upstream.
